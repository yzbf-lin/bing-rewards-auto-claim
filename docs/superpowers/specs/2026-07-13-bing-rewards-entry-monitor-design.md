# Bing Rewards 积分入口自动巡检扩展设计

## 目标

构建一个 Manifest V3 Chrome 扩展，每天自动验证 `https://rewards.bing.com/earn` 页面中下列四个区域的积分入口能否正常访问：

1. 连续打卡任务
2. 升级活动
3. 任务
4. 日常任务

扩展必须真实打开或点击当天页面上实际出现的每个可用入口，而不是仅发送后台 HTTP 请求。失败入口需要在扩展 Service Worker 控制台输出可定位的信息。用户还可以从扩展弹窗手动触发同一套巡检流程。

## 范围

### 包含

- 每天北京时间 09:00 自动巡检。
- Chrome 在 09:00 未运行时，当天首次启动后补跑一次。
- 动态发现四个区域中当天实际显示的入口，不依赖固定卡片数量或固定卡片名称。
- 支持普通链接、JavaScript 按钮、当前页跳转、新标签页和站内弹窗。
- 非活动标签页中的真实页面导航或 DOM 点击。
- 入口级结果、运行汇总和最近一次结果持久化。
- 弹窗手动执行、运行状态和最近一次结果展示。
- 自动关闭巡检产生的临时标签页。

### 不包含

- 自动完成搜索、答题、拼图、购买或其他入口打开后的业务任务。
- 绕过登录、验证码、账号等级或地域限制。
- 浏览器完全退出时在操作系统后台唤醒 Chrome。
- 远程通知、邮件、Webhook 或云端结果存储。
- 固定任务卡片清单的长期维护。

## 运行约束

- 自动巡检依赖 Chrome 运行。错过 09:00 时，只在当天首次启动后补跑。
- Chrome Alarm 是尽力调度：设备休眠或浏览器繁忙时可能晚于 09:00 触发，但恢复后仍执行当天任务。
- 扩展使用当前 Chrome 配置文件中的 Microsoft 登录态，不读取、导出或保存 Cookie。
- 打开某些入口可能使 Microsoft Rewards 将任务标记为已查看或已完成；这是用户确认接受的真实访问副作用。
- 因入口可跳转到当天动态生成的任意外部域名，扩展需要 `<all_urls>` 主机权限，并使用该权限观察顶层导航结果。
- 第一版只支持简体中文积分页，四个区域标题在规范化空白后必须与本文列出的中文标题完全匹配。

## 架构

### Service Worker

Service Worker 是唯一的任务编排器，包含以下职责：

- 创建和维护每天 09:00 的 `chrome.alarms` 定时任务。
- 在扩展启动时判断当天自动任务是否需要补跑。
- 接收弹窗的手动执行请求。
- 使用运行锁阻止两个巡检并发执行。
- 自动触发遇到运行锁时保存一个待执行自动任务；当前任务结束后立即执行，不能静默丢弃当天巡检。
- 按顺序执行入口，维护临时标签页集合，并在结束或异常时清理。
- 汇总结果、写入 `chrome.storage.local` 并输出控制台日志。

自动任务使用“当天已执行”标记去重。手动任务忽略该标记，但仍受运行锁保护。

### 页面采集器

页面采集器通过 `chrome.scripting.executeScript` 注入积分页。采集函数是可独立测试的纯 DOM 函数，并完成以下工作：

- 按可见的二级标题定位四个目标区域。
- 在每个区域的关联容器中识别可交互卡片。
- 提取区域、可访问名称、可见标题、禁用状态、目标 URL 和入口类型。
- 为本次页面会话中的可点击卡片写入临时 `data-*` 标识，供后续精确点击。
- 为每个入口生成可跨积分页重载使用的 `fingerprint`：区域键、入口类型、规范化标题、稳定 `href` 或稳定 `data-*` 属性，以及同指纹入口中的重复序号。
- 重新打开积分页后必须用完整 `fingerprint` 重新匹配。匹配结果不是唯一一个时，入口记为 `FAILED/ENTRY_NOT_UNIQUE`，不得猜测或点击第一个元素。

积分页为异步渲染页面。采集器最多等待 20 秒，直到文档可交互、四个目标标题均出现，并且各区域的入口集合连续两次观察保持稳定，两次观察至少间隔 500 毫秒。超时后基于最终 DOM 产生明确的页面、缺失区域或空区域结果。

如果某个目标区域缺失、存在但没有任何卡片，或无法完成采集，必须产生区域级 `FAILED` 结果，不能把“零入口”误报为成功。区域存在且至少有卡片，但卡片全部因账号等级禁用时，入口均记为 `SKIPPED`，区域本身不失败。

### 入口执行器

入口按顺序执行，避免大量标签页并发打开以及 Rewards 页面状态相互影响。

- 普通链接：使用 `chrome.tabs.create({ active: false })` 直接打开解析后的绝对 URL。
- 动态按钮：为该入口打开一个新的非活动积分页标签，重新采集并按完整 `fingerprint` 唯一定位元素，然后执行 DOM `click()`。
- 动态按钮点击后同时观察当前标签页导航、新标签页创建和站内弹窗变化。
- 当前积分页被按钮导航离开时，该标签页只用于当前入口；下一个动态按钮使用新的积分页环境。
- 每个入口结束后关闭其源标签页和目标标签页，用户原有标签页不纳入清理集合。

扩展只负责打开入口并确认其首个可交互结果，不继续执行目标页面内的任务。

点击前，执行器记录页面中所有可见的 `dialog`、`[role="dialog"]`、`[aria-modal="true"]`，以及被点击元素的 `aria-expanded` 和 `aria-controls` 状态。点击后通过 `MutationObserver` 监听，满足以下任一条件才记为 `effect=modal`：

- 一个点击前不存在或不可见的语义对话框变为可见，并包含非空可见文本；
- 被点击元素的 `aria-expanded` 从非 `true` 变为 `true`，且 `aria-controls` 指向的面板变为可见并包含非空可见文本。

普通 DOM 内容变化、积分数字变化或加载动画不算弹窗成功。弹窗观察与导航观察共享单入口 20 秒超时。

普通 Manifest V3 扩展不能生成浏览器认可的可信用户手势，第一版不申请高风险的 `debugger` 权限。因此动态按钮只支持当前 Rewards 页面接受 DOM `click()` 的处理器。真实页面验收必须覆盖当天出现的每类可用按钮：如果某个按钮仅因要求可信手势而无法触发，结果记为 `FAILED/AUTOMATION_BLOCKED`，日志必须说明“未能判定入口可访问性”，不能伪装成 HTTP 或入口故障。若当前页面存在这种按钮，扩展不能宣告完成，需要重新评估是否由用户授权增加 `debugger` 权限。

### 导航验证器

导航验证器将 `chrome.webRequest`、`chrome.webNavigation` 和 `chrome.tabs` 事件按 `tabId` 与单次入口执行关联起来：

- 记录顶层导航的最终 URL、最终 HTTP 状态码、错误和耗时。
- 跟随正常重定向，以最终页面作为判定对象。
- 当响应事件不可用但标签页成功完成加载时，使用浏览器加载状态作为降级信号，并在结果中标记状态码未知。
- 每个入口使用有限超时；默认 20 秒。
- 事件监听器在每个入口完成后立即移除，避免跨入口污染或内存泄漏。

最终导航只取 `type=main_frame`、属于当前源或目标 `tabId` 的最后一次成功完成事件；若没有对应的 `webRequest.onCompleted`，在 `tabs.onUpdated(status=complete)` 后读取该标签页 URL 作为降级最终 URL。以下规则固定用于特殊页面判定：

- 登录页：最终 URL 的主机名等于 `login.live.com`、`login.microsoftonline.com` 或 `login.microsoft.com`。
- 浏览器错误页：最终 URL 使用 `chrome-error:` 协议、以 `chrome://network-error/` 开头，或当前顶层导航收到 `webNavigation.onErrorOccurred` 且之后没有成功的顶层导航。
- 重定向链中的登录主机不单独失败；只判断最终 URL。

每个入口在触发动作前注册监听器和 DOM 观察器。得到第一个确定结果或超时后，以一次性 `settled` 标记冻结结果并忽略迟到事件；随后依次停止 DOM 观察、移除 Chrome 事件监听器、关闭本次创建的标签页，最后持久化并输出日志。标签页关闭事件只有在结果冻结前发生时才可将入口判为失败。

### 弹窗

弹窗提供以下信息和操作：

- 下次自动执行时间：北京时间 09:00。
- 当前状态：空闲、采集中、检查进度、已完成。
- “立即检查”按钮。运行中按钮禁用，防止重复启动。
- 最近一次运行时间、触发来源和 `PASSED / FAILED / SKIPPED` 汇总。
- 按四个目标区域展示入口名称、结果、耗时和失败原因。

弹窗通过消息请求执行，通过 `chrome.storage.onChanged` 更新进度，不持有任务状态。

## 数据模型

单个入口的采集描述：

```text
EntryDescriptor
  id              本次采集唯一 ID
  section         四个目标区域之一
  title           用于展示和日志的入口名称
  kind            link | button
  disabled        是否不可用
  url             链接入口的绝对 URL，可为空
  fingerprint     跨积分页重载重新定位按钮的稳定组合字段
```

统一结果记录，可表达入口、区域和页面错误：

```text
ResultRecord
  id
  scope           entry | section | page | run
  section         区域或入口结果使用
  title           入口结果使用
  outcome         PASSED | FAILED | SKIPPED
  effect          navigation | new_tab | modal | none
  finalUrl
  statusCode
  durationMs
  reason
```

单次运行记录：

```text
RunResult
  runId
  trigger         scheduled | startup_catch_up | manual
  startedAt
  finishedAt
  status          running | completed | aborted
  results[]
  summary
```

`chrome.storage.local` 只保留当前运行状态、最近一次完整结果和最后一次自动执行日期。入口结果不长期累积。

## 判定规则

### PASSED

满足以下任一条件：

- 页面或新标签页完成顶层加载，最终 HTTP 状态码小于 400，且没有导航错误。
- 点击后出现新的可见站内弹窗或对话框。
- 无法取得 HTTP 状态码，但目标标签页完成加载、最终 URL 使用 `http:` 或 `https:` 协议、URL 不是浏览器错误页或登录页，并且 DOM 探针确认 `document.readyState="complete"`、存在 `document.body`，且页面至少包含一个具有非零边界框的可见元素。

### FAILED

满足以下任一条件：

- 最终 HTTP 状态码大于等于 400。
- 当前入口的顶层导航发生错误，并且在该入口超时前没有后续成功的顶层导航完成事件。
- 页面进入 Chrome 网络错误页。
- 最终页面是 Microsoft 登录页，说明当前会话无法访问入口。
- 动态按钮点击后没有导航、新标签页或弹窗效果。
- 动态按钮只因缺少可信用户手势而无法触发；此时原因必须是 `AUTOMATION_BLOCKED`，不能声称入口本身不可访问。
- 单个入口超过 20 秒仍未得到有效结果。
- 目标区域缺失、目标区域为空、页面加载失败或采集失败。

### SKIPPED

- 卡片具有 `disabled`、`aria-disabled="true"` 或页面明确展示账号等级限制。

## 日志

每个入口都输出结构一致的单行日志：

- `console.info`：`PASSED`，包含区域、名称、最终 URL、状态码和耗时。
- `console.warn`：`SKIPPED`，包含区域、名称和跳过原因。
- `console.error`：`FAILED`，包含区域、名称、目标或最终 URL、状态码、耗时和错误原因。

运行结束输出汇总，包括触发来源、总数以及三类结果数量。日志不得包含 Cookie、请求头、页面正文或其他账号敏感信息。

## 调度

- 使用北京时间计算下一次 09:00 对应的绝对时间，并创建一次性 Alarm；每次触发后重新计算下一次时间，避免直接使用本地时区导致错误。
- `runtime.onInstalled` 和 `runtime.onStartup` 都会确保下一次 Alarm 存在。
- 启动时读取最后一次自动执行日期。如果北京时间当天尚未执行且当前时间已过 09:00，立即启动 `startup_catch_up`。
- `scheduled` 或 `startup_catch_up` 遇到手动任务占用运行锁时，写入持久化的单个 `pendingAutomaticRun`；当前任务的 `finally` 阶段立即消费该任务。多个自动触发只合并为一次。
- 自动运行结束后更新最后执行日期；运行整体异常时仍保存结果，但不把未开始的入口伪装成成功。
- 手动运行不会修改“当天自动任务已执行”标记。

## 权限

Manifest V3 需要以下权限：

- `alarms`：每日调度。
- `storage`：运行状态和最近结果。
- `tabs`：创建、观察和关闭临时标签页。
- `scripting`：在积分页采集和点击动态卡片。
- `webNavigation`：捕获顶层导航错误和完成事件。
- `webRequest`：读取导航响应状态码。
- `<all_urls>` 主机权限：访问动态目标并观察其导航结果。

不申请 Cookie、历史记录、下载、通知或调试器权限。

## 错误处理与清理

- 全局运行使用 `try/finally`，任何异常都必须释放运行锁并关闭本次创建的标签页。
- 单个入口失败不会终止整个巡检，后续入口继续执行。
- 积分页未登录或四个区域未加载时，记录页面级失败并结束本次运行。
- Service Worker 被 Chrome 挂起后，可从 `chrome.storage.local` 识别遗留的 `running` 状态；下一次启动将其标记为异常结束，并允许重新运行。
- 遗留运行被标记为 `aborted`，并增加 `scope=run` 的失败记录；页面级和区域级错误也使用统一 `ResultRecord`，不创建特殊的伪入口。
- 用户手动关闭临时标签页时，该入口记为失败并继续后续入口。

## 测试策略

### DOM 单元测试

使用固定 HTML fixture 覆盖：

- 四个区域及其边界识别。
- 普通链接与相对 URL 解析。
- 动态按钮和临时运行 ID。
- 禁用属性与等级限制文本。
- 同名入口。
- 区域缺失与空区域。
- 20 秒就绪超时与连续两次稳定观察。
- 简体中文标题精确匹配与空白规范化。

### 调度单元测试

- 北京时间 09:00 的下一次执行时间。
- 09:00 前不补跑、09:00 后补跑。
- 当天已自动执行时不重复补跑。
- 手动执行不受每日去重影响。
- 并发运行被拒绝。
- 自动触发与手动任务冲突时持久化排队，并在手动任务结束后执行一次。

### Runner 单元测试

使用受控 Chrome API fake 覆盖：

- 普通链接成功、重定向、4xx、5xx 和超时。
- 动态按钮触发当前页导航、新标签页和弹窗。
- 点击无响应。
- 入口重新采集后唯一匹配、找不到和同指纹不唯一。
- 缺少可信用户手势时记录 `AUTOMATION_BLOCKED`。
- 禁用入口跳过。
- 单项失败后继续。
- 监听器与临时标签页始终清理。

### 清单与人工验收

- 自动测试校验 Manifest V3、权限、Service Worker、弹窗和资源路径。
- 从当前真实页面裁剪并匿名化四个区域的代表性 DOM fixture，测试只保留结构、属性和占位文本，不保存账号数据。
- 在真实积分页执行一次手动巡检，确认四个区域被发现、标签页保持非活动、结果写入存储、失败日志格式正确并且临时标签页全部关闭。
- 真实页面验收必须确认当天每类动态按钮都接受 DOM `click()`；出现 `AUTOMATION_BLOCKED` 时不得宣告完成。
- 真实页面验收不固定卡片数量和名称，避免当天内容变化造成伪失败。

## 完成标准

- 解压加载扩展后，无需外部服务即可运行。
- 手动点击“立即检查”能够执行完整巡检并展示结果。
- 每天北京时间 09:00 自动执行，错过时间后当天启动可补跑。
- 四个区域中的可用入口均被真实打开或点击；禁用入口被明确跳过。
- 当天可用动态按钮均已验证不要求可信用户手势，结果中不存在 `AUTOMATION_BLOCKED`。
- 失败入口在 Service Worker 控制台包含足够的定位信息。
- 巡检不抢占当前活动标签页，不遗留临时标签页。
- 自动化测试通过，并完成一次真实页面验收。
