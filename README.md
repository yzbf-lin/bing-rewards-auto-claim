# Bing Rewards 自动领取

提供 **油猴脚本** 和适用于 **Google Chrome** 的 Manifest V3 扩展，用于处理 Microsoft Rewards 单步积分任务、每日单次搜索打卡、Bing 滑块拼图和仪表盘待领取积分。

**Microsoft Edge 暂不支持**：当前排查环境中，Edge 的浏览器访问限制阻止了 Rewards 页面的脚本注入。详见下方“Microsoft Edge：暂不支持”说明。

两种版本都无需构建或运行时依赖，支持手动执行和每日自动执行。

## 功能

- 扫描积分赚取页和积分首页的每日任务。
- 自动进入“赚取更多”对应的积分赚取页，扫描连续打卡任务、升级活动、任务和日常任务。
- 自动进入 `/earn/quest/` 任务详情，执行当前已解锁且标记为“点击即可完成”的 Bing 子任务。
- 使用页面元素特征评分识别新增单步任务，不依赖固定任务名称。
- 交互式测验、投票及带进度任务会跳过，不再误判为点击即完成。
- 完成任务后重新扫描 `https://rewards.bing.com/dashboard`，自动领取本轮新增及已有的“可领取”积分，包括弹窗二次确认；只有待领余额实际减少才记录领取成功。
- 支持待领积分与领取按钮分开的卡片、链接或 `role="button"` 入口，以及简体中文、繁体中文和英文领取按钮。余额为 0 时跳过领取；余额尚未加载时等待，超时后显示原因。
- 自动完成 Bing Spotlight `/spotlight/imagepuzzle` 的 3×3 滑块拼图：读取图片块编号、计算合法移动并逐步点击，以页面完成提示作为成功依据。支持普通布局和带开始按钮的布局。
- 支持“必应搜索连续打卡”中今日 `搜索 0/1` 的任务：先在面板设置中保存搜索词，运行时点击原始卡片、填写 Bing 搜索框并提交一次，再返回 Rewards 核对 `1/1`。不会仅因打开了搜索结果页就记为完成。
- 0.4.4 补齐 Rewards 实际使用的按钮入口：点击“必应搜索连续打卡”后，等待详情弹窗加载，再点击其中的“立即搜索”链接。0.4.3 仅处理直接链接，会将这种按钮卡片跳过为“需要继续交互”。
- 未保存搜索词时跳过搜索打卡并显示设置提示，不影响其他任务；搜索框不可用、提交失败或进度未更新时显示原因，不反复提交搜索。
- 自动打开“每日活动”中点击后立即获得积分的卡片。
- 兼容“每日活动”卡片只显示数字积分、未显示 `+` 号的页面结构。
- 兼容“日常任务”卡片只显示 `5`、`5 点` 等积分徽标的页面结构，直接点击类任务不再因缺少 `+` 号而跳过。
- 手动执行时在当前活动标签页中依次打开任务，不创建额外任务标签页。
- 从扩展商店或浏览器内部页面启动时，先跳转到 Rewards 页面并等待新页面加载完成，再注入脚本；进度浮球和任务脚本只注入受支持的 HTTPS Bing 页面。
- 页面默认显示蓝紫与青色流光的玻璃小球；悬停或键盘聚焦时平滑变为横向胶囊，点击展开完整领取面板。
- 小球支持拖拽，展开后可拖动面板顶部；自动记住位置、限制在可视范围内，拖动不会误触展开。点击收起按钮或按 Esc 恢复小球。
- 运行中小球会加快流光并显示“正在领取”，展开后可查看当前步骤、任务名称、进度和实时结果；遵循系统的减少动态效果设置。
- 手动执行完成后自动返回积分赚取页，并保留最终执行结果。
- 手动执行允许重复验证今天已触发的单步入口；每天的自动任务仍会避免重复触发。
- 每次当前标签页完成跳转后都会重新确认进度浮层已注入。
- 手动运行时，任务目录扫描和任务 URL 全部复用当前标签页，不创建临时标签页。
- 手动任务与工具栏弹窗生命周期解耦，弹窗收起后任务和页面进度面板继续运行。
- 页面面板和工具栏弹窗显示当前扩展版本；面板汇总每类跳过原因并在最近结果中标注原因。
- 页面浮动组件展开后直接嵌入工具栏的完整领取界面，共用同一套 HTML、CSS、状态列表和运行按钮。
- 已捕获的运行异常使用警告日志，避免浏览器将其记录成 `[object Object]` 扩展错误；真实原因会显示在运行面板和结果列表中。
- 完成状态会结合页面中的全部实时进度值判断；“已完成连续打卡 1 天”但“活动 0/3”的卡片会标记为需要继续交互，而不是此前已经完成。
- 只根据可见任务文字或明确的测验参数识别测验，避免内部 `REWARDSQUIZ` 路由标记造成误判。
- 每 6 小时检查一次 GitHub Release；发现新版本时显示红色角标、版本提示和下载按钮。
- 定时执行时使用后台临时标签页，完成后自动关闭。
- 记录最近识别的任务、执行结果、发现次数和成功次数。
- 同一天的自动运行不会重复执行已经成功触发的同一任务；“可领取”余额新增时仍可继续领取。
- 自动跳过未支持的拼图、多次搜索、购买、订阅、邀请、等级受限及其他需要继续交互的任务。
- 油猴版本使用单文件安装，通过 `GM_*` 存储在同一标签页的页面跳转之间恢复执行进度。
- 油猴版本通过脚本管理器检查 GitHub Raw 地址并自动提示更新。
- 链接任务会回到来源页重新定位并实际点击原始 Rewards 卡片，再在当前标签页继续打开目标页面，保留活动所需的点击记录。
- 多步骤任务每完成一个已解锁步骤后都会重新扫描详情页，将刚解锁的下一步加入当前执行队列。
- 油猴面板提供可展开的结构化运行日志，记录任务采集、卡片点击、跳过原因、动态重扫和失败信息。
- “每日活动”中带测验 URL 但点击卡片即可记账的入口会优先点击原卡片，不再仅因 `dsetqu` 参数而跳过。
- 多步骤任务点击后会重新读取详情页进度；进度未增长时记录“等待 24 小时”或“进度尚未增长”，不再把一次点击直接显示成任务完成。

## 快速安装

### 方式一：安装油猴脚本

1. 在 Google Chrome 中安装 [Tampermonkey](https://www.tampermonkey.net/) 或兼容的用户脚本管理器。
2. 在 Chrome 的扩展管理页打开 Tampermonkey 的详情，开启“允许用户脚本”，并允许其访问 Rewards 和 Bing 页面。[Chrome 138 及以上版本需要单独开启此权限](https://developer.chrome.com/docs/extensions/reference/api/userScripts)，开发者模式不能替代它。
3. 点击 [安装最新版油猴脚本](https://raw.githubusercontent.com/yzbf-lin/bing-rewards-auto-claim/main/userscript/bing-rewards-auto-claim.user.js)。
4. 在脚本管理器的安装页面确认安装。
5. 登录 Microsoft Rewards，然后打开或刷新 `https://rewards.bing.com/earn`。
6. 点击页面右上角玻璃小球，展开后点击“立即领取”，或使用脚本管理器菜单中的“Bing Rewards：立即领取”。

油猴脚本在北京时间 09:00 后首次打开 Rewards 页面时自动执行一次。执行过程中即使当前标签页跳转到 Bing 搜索页，脚本也会从 `GM_setValue` 保存的步骤继续运行并保持进度面板。

0.4.3 使用脚本管理器的 `GM_getTab`、`GM_saveTab` 和 `GM_getTabs` 识别执行标签页，避免多个 Rewards 页面重复提交同一搜索。更新脚本时保留这些权限，并刷新 Rewards 页面；运行中请保留发起任务的标签页。如果该标签页已关闭，可在另一个 Rewards 标签页手动点击“立即领取”重新开始。

同一浏览器建议只启用油猴脚本或扩展中的一种，避免两套每日任务同时触发。

### 方式二：下载扩展 Release 包

1. 打开仓库的 [Releases](../../releases/latest) 页面。
2. 下载 `bing-rewards-auto-claim-vX.Y.Z.zip`；油猴用户也可下载同一 Release 中的 `bing-rewards-auto-claim-vX.Y.Z.user.js`。
3. 将 ZIP 解压到一个长期保留的目录。
4. 按下面的 Chrome 安装步骤加载解压目录。

浏览器不会直接安装 ZIP 文件，必须先解压，并选择包含 `manifest.json` 的目录。

### Microsoft Edge：暂不支持

截至 2026-09-29，在 Edge 154.0.4258.37 / Tampermonkey 5.5.0 的排查环境中，访问 `https://rewards.bing.com/earn` 时，Edge 自身的扩展菜单显示“不允许在 rewards.bing.com 上使用扩展”，油猴提示“没有访问此页面的权限”。浏览器在脚本执行前阻止注入，因此浮球和自动领取均无法运行。

该环境已经开启扩展、“允许用户脚本”和所有站点访问权限；`edge://policy` 显示未设置策略，也未发现用户配置的受限站点。因此目前只能确认存在浏览器层面的扩展访问限制，不能将其认定为已配置的企业管理策略，也尚未确认是 Edge 内置限制还是浏览器缺陷。

当前版本不承诺 Edge 可用，改用独立扩展包也没有经过可用性验证。重新安装本项目脚本或修改浮球代码无法解除浏览器的注入限制，请使用 Chrome；本次排查中，相同油猴脚本在 Chrome 开启“允许用户脚本”后已恢复显示。

油猴官方仓库有[相似的 Edge 问题报告 #2857](https://github.com/Tampermonkey/tampermonkey/issues/2857)，已作为 [#2846](https://github.com/Tampermonkey/tampermonkey/issues/2846) 的重复问题关闭；这不代表已修复，也不能证明与 Rewards 属于同一原因。目前没有经验证适用于本问题的修复方案。

### Google Chrome

1. 打开 `chrome://extensions/`。
2. 开启“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择解压后的扩展目录。
5. 在 Chrome 中登录需要使用的 Microsoft Rewards 账号。
6. 固定扩展图标，点击“立即领取”进行首次验证。

更新扩展后，在扩展管理页点击“重新加载”，并刷新已打开的 Rewards 标签页。首次验证时，拼图应显示“拼图已完成并确认”；本轮最后会检查可领取积分，有余额且确认领取成功后显示“待领取积分已领取”。

### 方式三：从源码安装扩展

```bash
git clone https://github.com/yzbf-lin/bing-rewards-auto-claim.git
cd bing-rewards-auto-claim
npm test
```

然后在 Chrome 扩展管理页加载项目根目录。

## 使用

### 油猴脚本

- 页面面板的“立即领取”和脚本管理器菜单均可手动触发。
- 所有任务链接都在当前标签页打开；状态会在导航前保存，并在目标页面加载后继续执行。
- Rewards 页面默认显示玻璃小球，点击可展开面板；运行期间跳转到其他 Bing 页面时也会显示。每个新页面默认收起，拖拽位置会保留。
- 每天自动执行以浏览器已打开 Rewards 页面为触发条件；北京时间 09:00 后当天首次访问会补跑。
- 更新由 Tampermonkey 等脚本管理器根据元数据中的 `@updateURL` 和 `@downloadURL` 完成。

### 搜索打卡设置（0.4.3 起）

1. 展开玻璃小球，在领取面板中打开“搜索打卡设置”。
2. 填写“打卡搜索词”（单行、不超过 200 字），点击“保存搜索词”。搜索词仅保存在本机对应版本的存储中；油猴和独立扩展的设置互不共享。
3. 点击“立即领取”验证。后续每日自动运行会使用保存的搜索词；清空并保存后暂停这项搜索任务。

本功能只处理已识别的“必应搜索连续打卡”单次日进度，不会一次完成多天连续打卡，也不自动执行多次搜索任务。今日已达到 `1/1` 时不再搜索；返回页面后仍为 `0/1`、卡片消失或状态不明确时，记录“尚未确认今日打卡”，不会记录成功或自动反复搜索。

同一轮运行最多尝试一次搜索打卡，即使积分首页和积分赚取页同时展示该任务，也不会重复提交。

搜索词不会写入运行日志。积分和打卡是否记入以微软服务端及页面实际进度为准，不能保证固定重复搜索词每天都能记账。Microsoft Rewards 的搜索要求见[官方说明](https://support.microsoft.com/en-us/accounts-billing/rewards/limiting-your-searches-in-microsoft-rewards)。

### 手动执行

1. 点击浏览器工具栏中的扩展图标。
2. 点击“立即领取”。
3. 扩展会先读取任务，再在当前活动标签页中依次处理可执行入口。
4. 点击页面上的玻璃小球，展开面板查看当前步骤和处理结果；拖动小球或面板顶部可调整位置。
5. 执行结束后仍可展开查看完整结果。点击收起按钮或按 Esc 恢复小球，收起不影响后台任务。

当前标签页已经位于目标页面时，扩展会直接执行按钮操作，不等待不存在的页面跳转。

### 自动执行

- 浏览器运行时，每天北京时间 09:00 自动执行。
- 09:00 时浏览器未运行，当天首次启动后会补跑一次。
- 自动执行使用后台临时标签页，不会切换当前活动页面。

## 任务识别规则

以下入口会自动执行：

- 当前可用且尚未完成；
- 显示明确积分奖励；
- 只需打开一次链接或点击一次按钮；
- 积分首页“每日活动”分组中的可用积分卡片；
- 首页“可领取”积分及其“领取积分”确认按钮。
- Bing Spotlight 的 3×3 滑块拼图。
- 已保存搜索词，且今日搜索进度为 `0/1` 的“必应搜索连续打卡”。
- “任务”分组中已解锁、只需点击一次的活动子步骤。
- 置信度达到阈值，且具备可信链接、积分徽章、新窗口或“点击完成”等单步特征的入口。

以下任务会记录但默认跳过：

- 其他拼图、通过多天搜索/签到收集拼图块的活动、需要回答问题的测验或投票；
- 除上述单次搜索打卡外，需要多次搜索、连续多天签到或多步骤打卡；
- 购买、订阅、安装、邀请好友；
- 等级受限、已完成、禁用或奖励信息不明确的入口。

## 任务记录

扩展使用 `chrome.storage.local` 保存，油猴脚本使用 `GM_setValue` 保存：

- 最近一次执行结果；
- 北京时间自动执行日期；
- 任务稳定指纹和识别原因；
- 最近执行结果、发现次数及成功次数。
- 用户保存的打卡搜索词（不写入运行日志）。

最多保留 200 条任务记录。扩展不读取或保存 Cookie、密码及浏览历史。

## 权限

| 权限 | 用途 |
| --- | --- |
| `alarms` | 每天调度自动执行 |
| `storage` | 保存运行结果和任务识别记录 |
| `tabs` | 使用当前标签页或管理自动执行的临时标签页 |
| `scripting` | 读取积分卡片并触发领取按钮 |
| `downloads` | 下载检测到的新版 GitHub Release ZIP 包 |
| `https://*.bing.com/*` | 在 Rewards 与任务跳转后的 Bing 页面执行任务并显示进度面板 |
| `https://api.github.com/*` | 查询本项目最新的 GitHub Release 版本 |

## GitHub Release 更新提示

扩展启动后每 6 小时检查一次最新 Release。发现高于当前安装版本的新版本时：

1. 扩展图标显示红色 `↑` 角标；
2. 打开扩展弹窗会显示当前版本和最新版本；
3. 点击“下载更新”直接下载对应 ZIP；
4. 下载完成后解压覆盖旧目录，并在扩展管理页点击“重新加载”。

更新检查只访问本项目公开的 GitHub Releases API，不会上传浏览数据。

## 日志和排障

如果旧版从扩展商店页面启动时显示 `The extensions gallery cannot be scripted.`，请更新到 0.4.2 或更高版本并重新加载扩展。此场景下，更新会跳过商店页注入，进入 Rewards 后再执行。也可先打开 `https://rewards.bing.com/earn`，再点击“立即领取”。此修复不解除 Edge 对 Rewards 页面本身的扩展访问限制；遇到“不允许在 rewards.bing.com 上使用扩展”时，请参阅上方 Edge 暂不支持说明。

1. 打开 `chrome://extensions/`。
2. 找到“Bing Rewards 简单积分领取”。
3. 打开 Service Worker 的“检查视图”。
4. 查看 `CATALOG_LOADED`、`COMPLETED`、`SKIPPED`、`FAILED` 和 `RUN_FINISHED` 日志。

查看任务记录：

```js
chrome.storage.local.get(["taskMemory", "lastRun"]).then(console.log)
```

更新源码或覆盖已解压目录后，需要在扩展管理页点击“重新加载”。

## 开发

```bash
npm test
npm run validate
npm run package
```

- `npm test`：运行全部单元测试。
- `npm run validate`：检查 Manifest、引用文件和油猴脚本元数据。
- `npm run package`：在 `dist/` 生成扩展 ZIP 和单文件 `.user.js`。

扩展不需要安装 npm 依赖，也不需要前端构建步骤。

## Release

推送 `v*` 标签后，GitHub Actions 会：

1. 运行测试和扩展校验；
2. 打包扩展 ZIP 和油猴 `.user.js`；
3. 创建对应的 GitHub Release；
4. 上传可直接下载并解压使用的 ZIP 文件及可直接安装的油猴脚本。
